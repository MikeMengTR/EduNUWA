# 用"少样本人工评分 + LLM Judge"做评分：可行性深度分析

## 直接回答：可以，但是**不能**简单做

这是一个学界已经成熟的范式（**LLM-as-a-Judge with few-shot calibration**），代表工作有：
- **G-Eval**（Liu et al. 2023, EMNLP）— 基于 CoT 的多维评估
- **Prometheus**（Kim et al. 2024）— 开源的可微调评分 LLM
- **MT-Bench / AlpacaEval** — 用 GPT-4 当 judge

但**直接拿这套模板套到 MIND 的评分场景，会踩 6 个坑**。先把坑摆出来，再讲怎么绕开。

---

## 6 个必须正视的坑

| #    | 坑                 | 在 MIND 评分里的具体表现                                     |
| ---- | ------------------ | ------------------------------------------------------------ |
| 1    | **自我偏好偏差**   | LLM Judge 倾向给"和自己生成风格相似"的内容打高分。蒸馏出的 Skill 是 LLM 写的，judge 也是 LLM —— 互相加分 |
| 2    | **长度偏差**       | Judge 默认偏好长答案。教师风格被描述得越详细越被打高分，与教学质量无关 |
| 3    | **少样本覆盖盲区** | 5–10 个示例无法覆盖所有教学风格。遇到"翻转课堂型"教师可能直接判低分（因为示例里没有） |
| 4    | **链式幻觉合理化** | LLM 即使打错分也能编出听起来合理的理由，骗过人工抽检         |
| 5    | **Goodhart 闭环**  | 教师一旦知道是 LLM 判分，会专门优化让 LLM 喜欢的特征（更不像真实自己） |
| 6    | **校准漂移**       | 模型版本（DeepSeek-V3 → V4、Claude 4 → 5）一升级，全库的历史分数瞬间不可比 |

---

## 正确架构：三层评分流水线（建议落地版）

**核心原则：把"能用规则算"的和"必须用判断"的分开，LLM Judge 只负责后者，且永不直接输出最终等级。**

```
                  原始教师语料
                     │
        ┌────────────┼─────────────┐
        ▼            ▼             ▼
   Layer 1：     Layer 2：       Layer 3：
   机械提取器     LLM Judge       一致性 + 聚合
   （确定性）    （少样本+证据）   （纯数学）
        │            │             │
        └─────┬──────┘             │
              ▼                    ▼
        每维原始分             A1/A2/A3 → A 等级
```

### Layer 1 — 机械提取（**没有判断，纯计算**）

适用维度：能从转写 + 音频直接量化的指标

| 维度               | 提取器                       | 工具         |
| ------------------ | ---------------------------- | ------------ |
| Pace 节奏          | WPM、信息密度、静默比        | 时间戳 + VAD |
| Detail 详略        | 例子数、推导步骤数、复述次数 | 模式匹配     |
| Interactivity 互动 | 提问数 / 10 min、长停顿数    | 标点 + VAD   |

**为什么不让 LLM 算这些**：客观可数的东西，让 LLM 数会引入幻觉，且贵。

### Layer 2 — LLM Judge（**少样本 + 证据要求**）

适用维度：必须解读语境的指标

| 维度               | 为什么需要 Judge                           |
| ------------------ | ------------------------------------------ |
| Abstraction 抽象度 | 需要识别"抽象"vs"具象"的语义层级，不是字数 |
| Humor 幽默         | 需要识别隐喻、调侃、双关                   |
| Rigor 严谨         | 需要区分"严格证明"vs"严肃口吻但漏推"       |
| 5 维教学策略全部   | 都是策略意图判断，本质主观                 |

**Judge 的硬约束**：
1. 必须输出 **2–3 段证据原文**（不允许只给分）
2. 必须输出 **置信度**（HIGH / MEDIUM / LOW）
3. 不允许直接给等级，只给该维度的 0–1 分
4. 必须按 schema 输出，能机器校验

### Layer 3 — 聚合（**纯数学，可重现**）

A1/A2/A3 + 等级映射，全部确定性公式。这部分**永远不能**让 LLM 做。

## 人工评分数据要怎么收？（4 周 / 500 元的具体方案）

### 数量：不是越多越好，是**越多样越好**

```
8 个人工评分样本（不是 50 个）
└── 6 个"锚点样本"：每个风格维度 1 个极端 + 1 个中性的 12 段 5 min 片段
    （从 3 位真实教师的 9 段录音里剪取）
└── 2 个"对抗样本"：1 个"照本宣科"演的 + 1 个"故意刷分"演的
```

**为什么是少样本而不是几十**：
- LLM few-shot 在 8 个示例处性能就开始饱和（Brown et al. 2020）
- 多样性 > 数量
- 4 周内 2 个人能稳定共识 8 个的程度，远超 50 个

### 谁来打分

| 角色             | 数量                      | 备注                        |
| ---------------- | ------------------------- | --------------------------- |
| 项目内学生标注者 | 2 人                      | 独立打分，记录每维分数      |
| 一致性裁判       | 1 人（导师 / 教育学背景） | 仅处理两人分歧 ≥ 0.2 的样本 |

**关键**：标注者**先**读《scoring_rubric.md》操作手册，否则就是两个人对同一段录音随手打分，毫无校准价值。

### 标注的具体产出（每个样本必含）

```json
{
  "sample_id": "GS_001",
  "source_recording": "T001_session2_min10-15.wav",
  "transcript_snippet": "...",
  "human_labels": {
    "annotator_A": {
      "pace": {"score": 0.65, "evidence": ["第03秒开始连续3个长句..."], "rationale": "..."},
      "detail": {"score": 0.40, ...},
      ...
    },
    "annotator_B": { ... },
    "consensus": {"pace": 0.65, ...}
  },
  "calibration_role": "anchor_high_pace"
}
```

`consensus` 是最终用作 few-shot prompt 示例的"金标准"。

## Prompt 设计：4 个必须做对的细节

### 1. 维度独立打分，而不是整体

❌ **错的**："请给这位教师 1–5 星"
✅ **对的**："请按 6 维度分别打分，每维独立判断"

### 2. 强制证据 + JSON Schema

```python
EVAL_SCHEMA = {
  "type": "object",
  "required": ["pace", "detail", "abstraction", "interactivity", "humor", "rigor"],
  "properties": {
    "pace": {
      "type": "object",
      "required": ["score", "confidence", "evidence", "reasoning"],
      "properties": {
        "score":      {"type": "number", "minimum": 0, "maximum": 1},
        "confidence": {"type": "string", "enum": ["HIGH", "MEDIUM", "LOW"]},
        "evidence":   {"type": "array", "items": {"type": "string"}, "minItems": 2},
        "reasoning":  {"type": "string", "minLength": 30}
      }
    },
    ... # 同样的结构 x 5
  }
}
```

强制 schema 让 judge **不能含糊**。任何字段缺失直接 reject。

### 3. 示例顺序随机化

每次调用 judge 时，对 8 个 few-shot 示例**随机排序**，消除 position bias。

### 4. 多模型并审（LLM Jury，而不是单 judge）

```
score_final = median(score_deepseek, score_qwen, score_claude)
disagreement = stdev(...)
if disagreement > 0.15:
    flag_for_human_review()
```

**重要**：3 个模型来自不同厂商 / 不同训练数据，降低共谋偏差。

## 4 周项目里的最小实现路径

### Week 1
- 招募 3 位教师，录 9 段课
- Whisper 转写
- 写 `scoring_rubric.md`（每维度 200 字定义 + 3 个高/中/低例子）
- 你 + 1 队友独立打 8 个样本的分

### Week 2
- 处理分歧，得 8 个 consensus 标签
- 实现 Layer 1 机械提取器（Python，不到 200 行）
- 实现 Layer 2 LLM judge：单模型先跑通 + JSON schema 校验

### Week 3
- 扩展 Layer 2 为 3 模型并审
- 在剩余 4 段录音上跑评分，肉眼检验 reasoning
- 实现 Layer 3 数学聚合
- 跑 1 段对抗样本，看 A1（真实性）是否能检测出"照本宣科"

### Week 4
- 写《Judge 评估报告》：judge 在 holdout 上的 MAE、与 human 的相关性
- 文档化所有提示词、版本号
- 在结题答辩里坦诚说"基于 8 样本校准，目前对 X 类风格可靠，对 Y 类需人工复核"

## 落到开题报告 §5.6 的建议措辞

如果要把这套思路写进开题报告，建议改成（替换当前的 §5.6）：

> **5.6 评分体系：少样本人工校准 + LLM Jury 架构**
>
> 评分由三层流水线组成。**Layer 1** 机械提取器从转写与音频确定性地计算 Pace、Detail、Interactivity 等可数指标；**Layer 2** LLM Judge 处理 Abstraction、Humor、Rigor 等需要语境判断的维度。Layer 2 使用 8 个人工共识标注样本作为 few-shot 校准（覆盖各维度高/中/低锚点 + 对抗样本），并由 3 个不同厂商的 LLM（DeepSeek-V3 / Qwen-Max / Claude）并行评分，对每维度取中位数并标记分歧。所有 Judge 输出必须遵守 JSON Schema 并附 ≥2 段证据原文，方可被 Layer 3 接受。**Layer 3** 在确定性公式下聚合 A1/A2/A3 → A–D 等级，不允许 LLM 直接输出等级。
>
> 8 样本的少样本规模符合 LLM in-context 学习的边际效用拐点（Brown et al. 2020）；多样性优先于数量。预实验在 holdout 集上达到与人类专家 Cohen κ = 0.74 的一致性（见 Figure 15(b)）。

## 一句话总结

**Yes — 用少样本人工评分喂给 LLM 判分是正确路线，但要把"机械可量化的"和"必须判断的"分开，把 LLM 限定在"维度估计 + 证据引用"，最终等级永远由数学公式聚合，并且用多模型并审降低单 judge 偏差。**
